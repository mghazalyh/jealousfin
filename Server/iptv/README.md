# IPTV gateway and strict health observer

This is the portable source for the Mac Mini IPTV experiment, not part of the iOS binary. The existing Jellyfin-compatible HLS path remains the default. The PS3 profile is an encoder fixture only; a PS3 streaming route and physical playback are not implemented.

## Deployment

Set these environment variables in a protected local service configuration:
- JEALOUSFIN_BIND, JEALOUSFIN_PORT (defaults: loopback and 18796)
- JEALOUSFIN_STATE_DIR (private directory outside the repository)
- JEALOUSFIN_PROVIDER_URL (authorized Stremio-compatible provider base)
- JEALOUSFIN_USERNAME, JEALOUSFIN_PASSWORD, JEALOUSFIN_TOKEN, JEALOUSFIN_SERVER_ID (stable values supplied locally)
- JEALOUSFIN_DEVICE_URL (iOS LAN control URL), JEALOUSFIN_DEVICE_TOKEN (optional existing LAN authorization)

Run gateway.py and policy_observer.py as separate managed processes. Do not expose the plain HTTP endpoints to the public Internet. Keep the original gateway and client credentials until a controlled migration has been verified. Use a service manager with restart-on-failure and protected local logs. The observer polls every five seconds and never issues playback mutations. Its SQLite file stores attempt order, terminal failure events, hiatus, sustained session evidence, and resource samples; it is not a substitute for the native health ledger.

An optional local hiatus-seed.json in the state directory may contain an array of objects with id, at (ISO 8601), reason. Never commit deployment-specific data or secrets. The native app's record_channel_failure command requires explicit approval. Gateway filtering is independent of native health accounting; the client's hiatus screen only shows native ledger entries. Native and gateway exclusions may overlap.

Run python3 test_policy_observer.py for isolated policy checks. The first successful startup does not prove sustained playback. The observer can miss old events that have already rotated out of the device log window. It uses observed terminal failures, not individual retry errors, to avoid penalizing an otherwise successful session. A policy database outage fails closed; do not install a new IPA until policy readiness is verified.

## Future iOS deployment

Native defaults: strict hiatus, 10-second stall timeout, 5-second failure retry delay, advance on stall, user-configurable rotation interval. Rotation state is persisted by server, account and category and seeded once from available native ledger history. Existing settings and credentials remain intact. Active hot revisions and local rollback history reset on a different IPA version/build. A hot configuration or runtime override can still control policy. Device-owned Surf tracks actual channels; shared server-owned Surf does not pretend to identify underlying channels. Before installing a new IPA, activate and verify the SQLite-aware gateway; the new release discards the previous static adapter override and its exclusion snapshot. Do not embed fixed channel IDs or expiry dates in an IPA.

The PS3 profile is a separate JSON fixture for future development. Do not advertise a compatible PS3 endpoint until it has passed physical console testing.

## Offline compatibility snapshot

Use `python3 make_policy_snapshot.py /private/policy.sqlite3 /private/new-adapter.js` to generate an ABI-1 catalogue filter for older clients. This read-only generator is not an installer or continuous synchronization service. Keep the output private. Each activation can reconnect an older client. The gateway marker delegates ordering and exclusions to the SQLite-aware gateway. Run `python3 test_policy_snapshot.py` for regression checks.

## Policy v2 and acceptance

The new gateway requires an initialized complete SQLite catalogue, fails closed when policy is unavailable, returns the complete catalogue plus health only to opt-in clients, and rejects excluded PlaybackInfo before source resolution. Older clients still receive a filtered catalogue. The authenticated policy event endpoint deduplicates native failure and sustained-success reports; explicit approval is required for reinstatement. The default remains 3 days per failure, ban at 8. Gateway policy takes precedence over native settings. Idle resource entries expire; recently accessed active-channel entries are protected under pressure. See docs/native-release-acceptance.md for the mandatory live migration and physical/endurance checks.

## Runtime configuration reload

After deploying the reviewed gateway, place a validated `gateway-runtime.json` in its existing state directory using atomic replacement and a new revision. The gateway retains the last accepted configuration on invalid input and reports the active revision and fault via /trial-status. See [the ABI 3 contract](../../docs/hotpatch-platform-abi3.md#gateway) for allowed fields, bounds, and deployment limitations.

## Restart-safe quality and rotation

Gateway favorites are persisted atomically in private `favorites.json`; migration from a legacy gateway must export the full authenticated favorites catalogue before stopping it, and retain the original token, account/server ID and login credentials. Keep a consistent SQLite backup and checkpoint the current channel/category/pause/countdown. Existing attempt history is preserved. A legacy client requires a same-channel reload after a controlled gateway restart; opaque media handles are not portable across processes.

Explicitly sequenced complete HLS segments can be coalesced and cached for 45 seconds, with a 64 MiB global cap and 8 MiB item cap. Manifests, keys, byte ranges and unsequenced resources bypass caching. Private status exposes bounded per-channel delivery latency samples, errors and cache hits. This is delivery telemetry, not decoded frame cadence measurement, and does not transcode the stream.

The native app saves its scoped current channel, rotation pause and countdown independently of hot patch state. On startup or reconnect it chooses the newest eligible local or gateway checkpoint. If excluded, it uses the normal durable cycle instead. Live HLS resumes at a new playable position, not necessarily the exact prior frame.

On a successful catalogue fetch the gateway saves only channel names, source IDs and genres. Subsequent transient provider catalogue failures may use this known metadata snapshot, with explicit degraded status; playback resolution still uses the live provider. Segment delivery percentiles exclude cache hits. The latest media playlist duration and discontinuity count are separately exposed. Native telemetry reports contiguous buffer ahead, live-edge distance, item-level access-log totals, and decoded-frame sample freshness. Adaptive startup learning can extend, but never shorten, the configured timeout. These diagnostics do not establish displayed frame cadence or prove that judder is resolved.

## Current programme metadata

The provider catalogue's `description` (`Now: ... (until HH:MM)` and `Next: ... at HH:MM`) and `releaseInfo` (`Now · ...`) can identify a current programme. A background worker refreshes metadata every 60 seconds, independently of playback attempts, channel policy and catalogue identity. Records expire after 150 seconds without a successful refresh. Inconsistent/missing titles are omitted. CurrentProgram and LiveTv/Programs expose the current title; JealousfinProgramme retains the provider's next title and raw clock strings, observation timestamp and provenance. Those strings are not converted into UTC dates until the provider timezone is established. No fabricated programme durations, stream probes or media downloads are needed. The guide is current-only, not a complete EPG.

### Corroborated external schedule fallback

For an explicit mapping of 15 audited US FAST channel names, the Plex US and Samsung US XMLTV listings (public i.mjh.nz mirrors) are refreshed every 15 minutes on a separate daemon worker. The gateway only uses an external title if both mapped distributor IDs report a unique overlapping current programme with matching normalized title and start/end within 60 seconds. Primary provider metadata always wins. External programme labels include `Scheduled:` because distributor schedule agreement does not establish the identity of the actual provider stream. UTC timestamps come from XMLTV offsets; records are hidden at schedule end or after 30 minutes without a successful refresh. No additional upstream media requests or channel attempts occur. No fuzzy automatic channel mapping. Bounded gzip/XML parsing and error isolation protect playback; conflicting, absent, ambiguous or expired schedules are omitted. The source mirror is shared, so agreement is corroboration across distributor listings, not independent verification of actual decoded video.

### Active physical-viewing research priority

OpenCode research now distinguishes an actual progressing playback session from the gateway's short `activeProtectionSeconds` resource LRU guard. The gateway reads only the existing authenticated `/Sessions/Playing`, `/Progress`, `/Stopped` and `PlaybackInfo` bodies, validates `ItemId`/`MediaSourceId`, `PlaySessionId`, bounded `PositionTicks` and boolean `IsPaused`, and correlates the channel. A server-issued playback session or a recent real media request is required. A start event, player pause, operator stop, channel switch, stale progress (default 45 seconds) or a resource fetch alone cannot become active viewing.

After sustained progress (default 120 seconds), the channel gets active research priority ahead of background missing channels. The first attempt uses LOW (or the configured engineering HIGH/MAX). If no independently verified evidence appears, a bounded retry uses HIGH with jittered backoff (default 45/120/300 seconds), not the six-hour background cooldown. Attempts are deduplicated per active window and substantially identical failed prompts are suppressed for five minutes across pause/resume or a quick return. Background channels retain the six-hour cooldown. There is no daily quota and only one research subprocess per profile. `/trial-status` exposes bounded active-viewing hashes, attempt/variant/retry timing and no raw session identifiers.

### Structured schedule evidence and diagnostics

Research answers remain leads. Verification now accepts bounded JSON-LD (including `@graph` references), embedded JSON schedule objects, official/XMLTV documents with explicit UTC offsets, and explicit HTML schedule tables. Every format requires an exact station identity, the source's approved region and timezone-aware start/end. HTML tables additionally require an explicit page timezone and date, reject ambiguous/nonexistent DST wall times, and cannot stand alone unless a first-party structured source is used. Independent corroboration requires two distinct approved domains with matching series/episode identity and boundaries within 60 seconds. A single source is accepted only when it is a strong first-party structured schedule. SSRF, host allowlists, same-host redirects, size limits, DTD/entity rejection and URL policy are unchanged.

Accepted researched rows may carry a verified series/programme title, episode subtitle, season/episode numbers and episode-scoped season year into the existing `programme_item` passthrough. A series premiere or channel launch year is never copied into the episode/season year. `/trial-status` reports tool-call counts/status, empty or failed search outcomes, rejected source hosts and reasons, selected verification mode, and retry/variant timing without prompts, queries, transcripts or private URLs.

### Optional local audio episode evidence (wired, default off)

`episode_audio.py` now implements the reusable handoff from the existing same-session language decode/transcribe pass plus a bounded public-evidence adapter. `language_audio.Manager` exposes only an optional `on_speech` callback and passes the already-computed transient transcript once, after an allowed English, device-verified sample whose channel did not change. The callback extracts a small set of public-programme clues and immediately drops the transcript. It never captures audio, uses a microphone, stores recordings or transcripts, contacts an external AI service, changes the active Whisper worker or adds another Whisper model, and it never starts a second stream or sampling pass.

Promotion requires the exact fresh channel/launch and durable physical-visit identity from the language visit ledger, a short observation expiry, a programme match, one official broadcaster archive and at least one independent report that agree, and rejects ads, reused promos, generic references, conflicting dates, wrong programmes and ambiguous matches. A same-launch reload changes the stream generation but not the visit ID, so it stays one physical session; a job whose visit has ended is rejected as stale. Promotion is skipped while the device reports a user pause or stopped rotation. Public sources are discovered automatically inside the existing official/report host allowlists: reviewed non-date-specific official archive roots build dated URLs or scan a bounded index, and an optional bounded OpenCode websearch supplies URL leads only. The private `episode-sources.json` registry remains an optional per-series override; it is no longer required for each date. Candidate and parsed-evidence caches are bounded and refreshed by a separate prefetch worker only when the lane is enabled. A provider answer is never identity evidence; any fetch failure, blocked host, redirect outside the approved site or missing corroboration stays inconclusive instead of guessing. Content identity is kept separate from scheduled-airing verification, official broadcaster numbering wins over conflicting third-party numbering, and the official original air date is retained; a series premiere year is never substituted for an episode year. Active viewing is prioritized with bounded attempts, cooldowns, cross-session clue deduplication, a daily cap and a per-visit publication guard. The feature is default OFF (`/trial-status` reports `episodeAudio.enabled=false`), and no live research or additional capture is active.

### Programme release years

A separate worker looks up exact programme titles in Cinemeta movie and series catalogues, prioritizing recently active channels. Accept a supplied parenthesized release year or a unique exact title across both result sets; ambiguous remakes require matching synopsis phrases or two cast names from corroborated guide evidence. Never choose by popularity or programme broadcast date. The catalogue release year is used (festival and theatrical release years may differ). Cache positive results for seven days and unresolved results for six hours, capped at 2048 hashed context keys. Bounded responses, request timeouts, a three-second worker interval and error backoff keep metadata off the playback path. Return ProductionYear and append (YYYY) to the programme display name only when matched; preserve provenance and avoid duplicate years. No AI, API key, or media decoding is involved.

Individual lookup errors defer only the affected title for 15 minutes; the worker keeps resolving other programmes. Denied/missing candidate detail records are not retried within the same lookup. A positive distinctive synopsis/cast match can resolve a title even if an alternative detail record is unavailable, but ambiguous/no positive evidence remains unresolved. Worker faults, deferred counts and sanitized per-title error codes are exposed separately; no private URLs are logged.

### Permanent episode metadata

A separate bounded Pluto US XMLTV worker refreshes every 15 minutes. Explicit reviewed distributor/provider identities require the current primary series title to agree, and exactly one current schedule row. Episode subtitle is available immediately; canonical season/episode numbers and the season's first episode release year require an exact-title match to Cinemeta series metadata. Unique canonical episode title can correct inconsistent distributor numbering; ambiguous or unavailable matches omit numbers/year. The worker is rate bounded and caches results for seven days, unresolved results six hours and transient failures fifteen minutes; no AI or stream requests are used. Episode IDs include the broadcast interval. Episode metadata expires at the schedule boundary or guide freshness limit. Dedicated series channels omit duplicate series names; mixed channels retain them. ProductionYear remains the series year while seasonYear is distinct. Single-distributor schedule evidence is not decoded-video verification. No automatic policy/rotation changes.

### Isolated Malay prototype (opt-in, not deployed)

The American source remains the default and preserves existing channel IDs, port and state directory. Set JEALOUSFIN_SOURCE_PROFILE=malay for a separate instance on port 18797 (or another non-production port), using the same gateway and observer implementation. Both processes receive the same existing state-directory base; the Malay profile automatically uses its profiles/malay subdirectory. Supply its own provider URL, separately provisioned server identity and credentials, and an explicitly reviewed JEALOUSFIN_PROFILE_MIN_CHANNELS after successful catalogue discovery. The gateway accepts a manifest or playlist.m3u suffix as well as an addon base. A first-start denied or incomplete catalogue fails closed before policy seeding. Existing American metadata, rotation files, health, favorites and cache are never used by the Malay profile. Channel IDs are namespaced for Malay and remain byte-for-byte unchanged for American. The same strict progressive hiatus policy and playback telemetry are used. Do not start both observers against the same database. No new daemon or automatic schedule is required for preflight. Do not enable the pilot until its catalogue and stream endpoints work and actual channel count has been reviewed.

Current installed client does not expose a source-connection-switch command to the overlay. Until a supported command exists, switch only through the existing native server connection settings, using the independent gateway origin and separately provisioned account. Rotation scope already includes the server URL. Restore the original American origin/account and original UI revision to roll back. An overlay button must not be wired to unrelated commands or policy events to simulate switching.

### Installed-client source selector compatibility experiment

An optional prototype-source-selector.json in the American state root enables same-origin dispatch for one configured LAN iPad only. The format is {"schemaVersion":1,"deviceIP":"192.168.31.82","backendPort":18797}. This is an opt-in experiment: the existing Movies & Series Surf preference becomes the Malay source alias, with a temporary selection tag on Malay catalogue entries only. All Channels remains American, preserving the prior native rotation scope. Native Sports/Favorites remain American. UI must display source buttons rather than the reserved category selector, and explicitly stop, change preference, refresh the catalogue, and start Surf in that order, checking each receipt. The backend uses the installed native LAN status contract to determine the selected category, routes channel-ID operations to their owning database, and proxies only the explicit local Malay media namespace. Policy snapshots are never forged. An unavailable backend/status returns 503, not a fallback mixed catalogue. Removing the opt-in file restores baseline server routing; first use the American selector and verify the production catalogue, then remove the file, reset UI, stop the isolated Malay processes. This uses the existing native category namespace temporarily; it is not a permanent native source-setting implementation. The native source promotion (source branch, not deployed by this change) uses the same American `All Channels` and Malay `Movies & Series` aliases and performs the same stop/preference/refresh/start sequence; it does not change this gateway protocol or require a gateway restart.

### Source-owned telemetry and catalogue changes
The observer uses the gateway's validated `trial-info.json` membership for current rotation counts, retaining historical policy rows even when the provider removes a channel. Both source observers record new system samples with channel ID and profile; old name-only samples are retained, not retrospectively rewritten. The `catalogue_observations` table records baseline and subsequent membership changes. Observer maintenance and heartbeat continue while the other source plays.

Run `python3 telemetry_report.py --root <profile-state-directory> --profile american --hours 24` (or `--profile malay` with its own directory) for read-only source-owned session, startup, buffer and resource metrics. Negative/zero bitrate sentinels are excluded; observed transfer bitrate and indicated encoded-media bitrate are not equivalent. Gateway source-error records distinguish explicit policy/selector infrastructure errors, upstream HTTP/transport evidence, and unresolved failures. Request counts are not channel-failure counts and cannot independently modify hiatus. Research only consumes model budget for regions with at least two approved guide domains; unsupported regions remain unverified until deterministic guide support is added.
